## The Appearance of Democracy: How Conditional Payments Reshape Behavior Among Local Leaders

**Authors**: Ivo Steimanis<sup>1,+</sup>, Esther Blanco<sup>2,3</sup>, Bjorn Vollan<sup>1</sup>

<sup>1</sup> Department of Economics, Philipps University Marburg, Germany
<sup>2</sup> Department of Public Finance, University of Innsbruck, Austria
<sup>3</sup> The Ostrom Workshop, Indiana University, USA
<sup>+</sup> Corresponding author: ivo.steimanis@staff.uni-marburg.de

**Published in**: Ecological Economics

**Keywords**: conditional payments, democratic governance, lab-in-the-field experiment, local leaders, environmental governance, Namibia, crowding out

**Note**: This study was not pre-registered. Data collection (2014) predates widespread adoption of pre-registration for lab-in-the-field experiments.

## Overview

This repository contains the data, code, and materials to replicate all tables and figures reported in the paper and its supplementary online material (SOM). The study uses a lab-in-the-field experiment with 64 local leaders and 384 villagers across 32 villages in the Ohangwena region of northern Namibia to examine whether conditional payments for democratic governance crowd in or crowd out democratic behavior among local leaders who manage communal natural resources.

---

## Quick start

1. Download or clone this repository.
2. Open Stata and run `do run.do`. The script resolves the package root from its own path, so your working directory does not matter.
3. Run the two R scripts and the Python script (see [Running the full pipeline](#running-the-full-pipeline)).

All output is written to `results/figures/` and `results/tables/`.

## Software requirements

| Component | Version used | Needed for |
|---|---|---|
| Stata | 19.5 (StataNow, BE) | Everything except Figures S2, S4 and Figure 4 |
| R | 4.3.1 | Figures S2 and S4 |
| Python | 3.13.0 | Figure 4 |

`run.do` sets `version 19.5`. The code uses no syntax specific to that release; if you are on an earlier Stata, lower that line.

R packages, at the versions used to generate the published figures: `TOSTER` 0.8.6, `haven` 2.5.4, `ggplot2` 4.0.2, `ggalluvial` 0.12.6, `dplyr` 1.1.4, `tidyr` 1.3.1. Both R scripts check that these are installed and stop with an informative message if any is missing; neither installs anything into your library. Each prints the versions actually in use, so divergence shows up in the log. `07_equivalence_tests.R` indexes the TOSTER result object positionally, which is the one place where a TOSTER version bump is likely to bite.

Python packages are pinned in `requirements.txt` (`pip install -r requirements.txt`).

All required Stata add-ons are vendored under `scripts/libraries/stata/`, and `run.do` puts them on the `adopath`, so nothing needs installing. The packages actually used are `estout` (`esttab`, `eststo`, `estadd`, `estpost`), `coefplot`, `catplot`, `grstyle`, `grc1leg`, `mylabels`, `colrspace`/`palettes`, and `ietoolkit` (`iebaltab`). `_install_stata_packages.do` is retained to document provenance; it is not called by `run.do` and you should not need it.

## Running the full pipeline

Stata must run first: the R and Python scripts read the datasets it writes to `processed/`.

```bash
# 1. Stata
stata-be -b do run.do

# 2. R (Figures S2 and S4)
Rscript scripts/07_equivalence_tests.R
Rscript scripts/08_transition_sankey.R

# 3. Python (Figure 4)
pip install -r requirements.txt
python scripts/fig4a_panel.py
```

`run.do` prints `PIPELINE_COMPLETE` as its last action before closing the log, so you can confirm the Stata half finished rather than aborting partway.

## Data anonymization

The data here have been de-identified before publication. The following were removed and cannot be recovered from these files or from this code:

- **Participant, interviewer, and social-network nominee names.**
- **Village names.** `village` is a numeric identifier, 1-32, using the same coding in the leader and villager files, so village fixed effects are unaffected. Names were removed because each village contributed exactly one traditional authority and one elected water point committee chairperson; a named village combined with a leader role would identify both individuals.
- **Open-ended survey responses**, including the stated motivation for becoming a leader, religious affiliation, and a series of free-text comment fields. Where a response fed a coded analysis variable, the coding was applied before publication and the coded variable ships in `data/`. This applies to `motivation` (intrinsic vs. extrinsic) and `religion`.
- **Ethnicity, clan, kinship relations, and social-network nominee positions.** None of these enters any analysis reported in the paper.

One consequence for replication: `motivation` is the hand-coded intrinsic/extrinsic classification described in `02_generate.do`. Four coders applied the rule independently (Fleiss' kappa 0.87, 88 percent agreement). Because the underlying response text is not published, that single coding step cannot be re-executed from these files; everything downstream of it can. Researchers who need the text for methodological work should contact the corresponding author, who can make it available under a data use agreement.

`01_clean.do` and `02_generate.do` each carry an explicit drop block before every `save`, listing the identifier and free-text fields by name. In a clean run those drops are no-ops. They are a deliberate last line of defence and should not be removed.

## Data description

### Raw data

| File | Description | Observations |
|---|---|---|
| `leader_raw.dta` | Leader survey and experimental decisions | 64 |
| `villagers_raw.dta` | Villager survey and voting decisions | 384 |
| `afro_r6.dta` | Afrobarometer Round 6, Namibia subset | varies |

### Key variables, `analysis_wide.dta` (1 row per participant, N = 448)

| Variable | Description | Values |
|---|---|---|
| `id` | Participant identifier | 1-64 leaders, 65-448 villagers |
| `village` | Village identifier | 1-32 |
| `leader` / `TL` | Leader type | 1 = Chief (TL), 0 = DEL |
| `villager` | Villager indicator | 0/1 |
| `rule1`-`rule6` | Rule choices (rounds 1-4 baseline, 5-6 bonus) | 1 = Democratic, 2 = Pseudo-democratic, 3 = Autocratic |
| `vote1`-`vote6` | Allocation choices | 1 = A (leader-favoring), 2 = B (egalitarian) |
| `motivation` | Intrinsic/extrinsic (leaders only) | 0 = Extrinsic, 1 = Intrinsic |
| `authentic_leader1` | Authentic leadership score | 0 = Low, 1 = High |
| `leader_type` | Baseline leader typology | 1 = True democrat ... 5 = Benevolent autocrat |
| `social_type` | Social preference type (Game 2) | 1-6 |
| `satisfaction_leader` | Villager satisfaction with matched leader | 1-5 |
| `pca_wealth` | Socio-economic status (PCA) | continuous |

### Key variables, `analysis_long.dta` (1 row per leader-decision, N = 192)

| Variable | Description | Values |
|---|---|---|
| `decision` | Decision round | 1 = Baseline, 5 = Bonus 1, 6 = Bonus 2 |
| `rule` | Rule choice | 1 = Democratic, 2 = Pseudo-democratic, 3 = Autocratic |
| `dem` / `fake` / `dic` | Binary rule choice dummies | 0/1 |
| `bonus` | Bonus round indicator | 0 = Baseline, 1 = Bonus |
| `bonus_size` | Bonus magnitude | 0 = Baseline, 1 = Small (N$10), 2 = Large (N$100) |
| `bonus_order` | Randomization order | 1 = Small first, 0 = Large first |
| `rule_basic` | Baseline rule choice, carried forward | 1 = Democratic, 2 = Pseudo, 3 = Autocratic |
| `type` | 4-box typology (motivation x baseline rule) | Box I-IV |

### Experimental parameters

| Parameter | Value |
|---|---|
| Villages | 32 (Ohangwena region, Namibia) |
| Leaders per village | 2 (1 chief/TL + 1 DEL) |
| Villagers per village | 12 (2 related to chief, 2 related to DEL, 8 neutral) |
| Small bonus | N$10 |
| Large bonus | N$100 |
| Bonus order | Randomized (34 leaders small-first, 30 large-first) |

## Missing value treatment

| Variable group | Treatment | Rationale |
|---|---|---|
| Satisfaction items (b10b, b11b-h, b12) | Missing to "don't know" (5) to neutral midpoint (3) | Treats non-response as neither satisfied nor dissatisfied |
| Democratic norm items (c1-c12) | Missing to 0 to neutral midpoint (3) | Treats non-response as neither agreeing nor disagreeing |
| Leadership motivation (f6) | Empty response coded extrinsic (0) | Leaders who gave no stated reason are treated as extrinsically motivated |

These decisions are implemented and commented in `02_generate.do`.

## Known deviations and caveats

- **Figure S4 (transitions).** The SOM caption refers to the "first bonus round". The figure is in fact built on the **small-bonus** round, which is round 5 for leaders randomized to small-first and round 6 for leaders randomized to large-first. Using round 5 for everyone instead gives 5 rather than 6 autocrats switching to democracy, and 8 rather than 9 democrats switching to pseudo-democracy. The code reproduces the published figure and documents the definition in a comment.
- **`motivation` cannot be re-derived** from the published files; see [Data anonymization](#data-anonymization).
- **Nothing in the pipeline is stochastic.** No seeds are set because none are needed: the estimation commands used (`xtprobit`, `xtmixed`, `mprobit`, `power`) are deterministic given the data.
